# RTT Code Map 设计说明

## 目标

制作一个独立运行、简体中文优先的 Windows 桌面应用，帮助 RT-Thread / RT-Thread Studio 用户理解本地 C/C++ 工程。用户通过“打开文件夹”选择工程；应用分析文件依赖和函数调用关系，在交互图谱中浏览调用链，并可用 LLM 解读、排查问题和生成测试建议。自动发现 VS Code 的安装路径仅用于从图谱跳转到源码，不作为应用运行时或工程发现机制。

## 用户与首版成功标准

首要用户是正在维护或学习 RT-Thread C/C++ 工程、希望通过直观图谱和中文 AI 辅助理解代码的开发者。首版需满足：

1. 安装并启动独立的 Windows x64 中文桌面程序，不要求安装 VS Code 或 Trae。
2. 使用清楚可见的“打开文件夹”入口导入本地工程；不要求自动判断当前 IDE 工程。
3. 自动发现 VS Code；发现失败可手动指定 `Code.exe`。点击符号可跳到对应文件和行号；未配置 VS Code 时仍可在应用内查看源码。
4. 显示目录/文件依赖视图和函数调用图，支持搜索、逐层展开、调用方/被调用方导航以及调用路径追踪。
5. 显示本地 Git 改动对函数和调用方的影响；没有 Git 或 Git 信息不足时说明原因，并保留普通图谱功能。
6. 支持配置主流 LLM 服务，对当前选中的调用路径、函数或 Git 改动进行中文解读、问题排查、测试建议和自定义提问。
7. 无法确定的静态调用边明确标为近似或未解析；发送给 LLM 的代码上下文可先预览并脱敏。

## 非目标

- 不把 Code Graph View 的 VS Code 扩展直接塞进 RT-Thread Studio，也不依赖 VS Code 扩展宿主。
- 不把 VS Code 作为本应用的运行时或必要依赖。
- 首版不模拟 RTOS 调度，不推导运行时调用，也不保证解析函数指针、宏生成代码、反射式调用或动态分发。
- 首版不自动上传工程，不默认把源码发送给 LLM；由用户主动发起分析并确认上下文。
- 首版不做完整 IDE 替代品；源码阅读提供轻量预览，编辑交给用户选择的外部编辑器。
- 首版不做 GitHub 账号授权和云端 PR 管理；本地仓库的工作区/暂存区/分支比较为主。

## 方案与架构

采用 Electron + TypeScript + React 构建独立 Windows 桌面应用。桌面壳、项目扫描、静态分析、图谱视图、Git 分析、LLM 提供方适配和外部编辑器启动器分层实现。

```text
用户点击“打开文件夹”
        │
        ▼
本地 C/C++ 工程 ──► 静态解析/编译信息 ──► 符号与依赖图
                                              │
                     ┌────────────────────────┼────────────────────┐
                     ▼                        ▼                    ▼
                 中文图谱视图             Git 影响分析          源码预览
                     │                        │                    │
                     └──── 用户选中上下文 ────┘                    └─► VS Code --goto
                                     │
                                     ▼
                          上下文预览/凭据脱敏
                                     │ 用户确认
                                     ▼
                              配置的 LLM 服务
```

### 工程分析与图谱

用户明确选择工程目录，扫描器展示文件计数、进度、取消入口和解析告警。优先读取 `compile_commands.json`；对 RT-Thread Studio 工程尽量提取常见 `.cproject`、Makefile 和 include 信息。C/C++ 语法树负责符号、包含关系和调用表达式提取；有可用编译参数时使用 Clang/clangd 提升跨文件解析准确度。没有编译数据库或工具链信息时允许以静态语法和名称匹配降级分析，并将近似边与未解析符号标清楚，不阻断工程浏览。

图谱主视图支持目录/文件依赖与函数调用层级；在函数节点上可查看上游调用者、下游被调用者、逐跳展开和完整追踪路径。支持搜索、重定位图中心、折叠/展开、深度限制、图例、边来源/置信状态说明和点击跳转源码。对大工程默认先展示目录/文件结构，再按需展开函数细节。

### Git 变更影响

在工程为 Git 仓库时，读取工作区与暂存区改动，并允许对比本地分支/提交。将变更定位到受影响的函数和调用方，显示签名变化、未同步调整的调用位置、相关测试线索等提示。结果是静态风险提示而非正确性证明；Git 不可用、仓库状态异常或基准分支不存在时，展示可读原因并禁用对应比较操作。

### LLM 供应商与分析

采用供应商适配层，首版支持 OpenAI 兼容 Chat Completions、Anthropic Messages 和 Google Gemini 原生接口；常见兼容服务提供预设，并支持自定义名称、API 地址、模型名、密钥和参数。供应商预设的名称/地址在实施时按官方文档核验，避免将过期地址写死。

用户可从调用图或 Git 改动中选择上下文，使用内置操作（解释调用链、分析潜在问题、提出测试用例）或输入自定义问题。发送前显示将发送的文件、函数和代码片段，默认掩码常见凭据；用户确认后才发送。保存的密钥用 Windows 本地安全存储能力保护。网络请求失败、限流、权限错误和模型不兼容都要给出中文的下一步提示，并允许重试或复制上下文自行使用。

### VS Code 定位与源码导航

VS Code 路径探测顺序为 PATH 中的 `code` 命令、Windows 应用注册信息、常见用户/系统安装目录；失败后提供手动选择 `Code.exe`。检测结果可修改。应用通过 `--goto 文件:行号` 打开位置。独立源码预览始终可用；VS Code 未安装、CLI 不可用或命令失败时展示错误并允许复制文件路径，不影响图谱和 LLM 功能。

## 中文界面与交互

主窗口包含项目打开入口、最近工程列表、左侧工程/符号导航、中央图谱画布、右侧详情与 AI 分析面板。首次打开时用简短向导解释选择工程、配置模型和开始分析；LLM 配置可跳过。常用操作有明确文字按钮、快捷键提示、空状态说明和可撤销/重试入口。术语统一用中文，原始符号名、路径、编译器错误保持原样以便搜索。

## 本地数据与隐私

源码索引和用户设置保存在本机应用数据目录。首版没有账号、遥测或后台云端索引。只有用户在 AI 面板明确发起并确认后，所选代码上下文才发送到已配置的供应商。提供上下文预览、凭据脱敏和清空本地索引/配置的入口。Git 分析只读取本地仓库元数据，不推送或改写提交。

## 交付方式

首版目标为 x64 Windows 独立安装包。安装包包含桌面应用运行所需依赖，不捆绑或复制 VS Code。应用可在完全没有 VS Code 的机器上完成工程分析、图谱浏览和源码预览；外部跳转功能可稍后配置。

## 风险与处理

- **调用关系可能不完整：** 编译数据库和 Clang 可用时优先走语义解析；降级结果标注来源与不确定性，保留源码跳转验证。
- **Studio 工程的编译配置不统一：** 先支持标准编译数据库和常见工程结构；解析不到的 include/宏在界面明确提示，允许后续增加配置导入。
- **不同 LLM API 有差异：** 按协议适配，供应商预设需验证；未知兼容端点可用自定义配置，失败时提供原始服务错误摘要。
- **源码隐私和密钥安全：** 不做自动云上传，发送前预览与确认，掩码常见密钥字段并使用 Windows 安全存储。
- **大工程图谱过密：** 默认模块视图、按需展开、最大深度设置与扫描取消。
- **编辑器启动差异：** 自动探测后可手动覆盖，源码内置预览作为稳定回退。

## 验收与验证

人工验收以下场景：在无 VS Code 配置时打开 RT-Thread 样例工程并浏览/预览源码；设置或自动发现 VS Code 后从图节点跳到正确文件行；在有 Git 与无 Git 工程中分别使用图谱和影响分析；配置各协议的测试端点验证中文 AI 请求、上下文预览和脱敏；在网络错误/凭据错误时看到可操作提示；确认界面以简体中文为主且未经确认不会把源码发给服务商。

## 后续迭代

首版后评估 RTOS 任务/中断视图、更多嵌入式工具链的编译参数提取、运行时 trace 导入、PR 平台集成、团队共享索引和其他编辑器跳转适配。
