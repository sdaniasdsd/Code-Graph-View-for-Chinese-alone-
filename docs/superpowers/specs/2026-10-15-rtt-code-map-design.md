# RTT Code Map 设计说明

## 目标

制作一个独立运行的 Windows 中文桌面应用，帮助 RT-Thread / RT-Thread Studio 用户快速看懂 C/C++ 工程的文件依赖和函数调用关系。应用可自动发现本机 VS Code，用它打开图谱中选中的源文件和行号；VS Code 不存在时，项目导入和图谱浏览仍可使用。

## 用户与首版成功标准

首要用户是正在维护或学习 RT-Thread C/C++ 工程、但不想依赖 VS Code 扩展的开发者。首版需满足：

1. 安装并启动一个独立的中文 Windows 桌面程序。
2. 自动发现 VS Code；若发现失败，可在设置中手动指定 `Code.exe`。
3. 导入一个本地 C/C++ 工程，显示文件/模块依赖图和函数调用图。
4. 点击图中符号可查看源代码位置，并可通过 VS Code 打开该文件及行号。
5. 无法确定的调用边明确显示为“可能调用”或“未解析”，不伪装成确定结论。

## 非目标

- 不把 Code Graph View 的 VS Code 扩展直接塞进 RT-Thread Studio。
- 不把 VS Code 作为本应用的运行时或必要依赖。
- 首版不模拟 RTOS 调度，不推导运行时调用，也不保证解析函数指针、宏生成代码、反射式调用或动态分发。
- 首版不向网络上传工程，不调用云端 AI。
- 首版不做代码编辑器替代品；源码阅读与编辑交给 VS Code 或应用中的轻量预览。

## 方案与架构

采用 Electron + TypeScript + React 构建独立 Windows 桌面应用。桌面壳、静态分析、图谱视图和 VS Code 启动器保持分层，避免图形界面与分析器互相依赖。

```text
RT-Thread Studio 工程目录
        │
        ├── C/C++ 文件与 include 信息
        ▼
本地静态分析器 ──► 符号/依赖图数据 ──► 中文交互式图谱
                                             │
                                             └──► VS Code 启动器 --goto 文件:行号
```

VS Code 定位顺序：PATH 中的 `code` 命令、Windows 应用注册信息、常见用户/系统安装目录；若都未命中则由用户手动选择可执行文件。检测结果允许在设置中修改。路径只用于打开源码，不参与分析。

源码分析首版以本地静态解析为基础：扫描 C/C++ 源文件、提取函数定义/调用表达式与 `#include`，形成文件级依赖和函数级调用关系。可利用 `compile_commands.json` 提供的编译信息改善解析；没有编译数据库时使用语法树与名称匹配，并将不确定关系标为近似。跨文件同名函数、宏、函数指针等情况不得默认为精确解析。

图谱支持按文件/模块与函数两个层级切换、搜索符号、限制展开深度、显示调用方/被调用方、跳转到源文件。首版需要基础空状态、扫描进度、无效工程提示、解析警告、VS Code 未找到提示和手动路径入口。

## 本地数据与隐私

源码分析在本机完成。工程索引和用户设置保存在本机应用数据目录。首版没有遥测、账号或云端处理。工程过大时提供取消扫描能力，并避免一次性渲染全部符号。

## 交付方式

首版目标为 x64 Windows 独立安装包。安装包包含应用运行所需依赖；不捆绑或复制 VS Code。应用首次运行可跳过 VS Code 定位，之后仍可从设置补充路径。

## 风险与处理

- **静态调用关系会有遗漏或误判：** 优先使用编译数据库；对名称匹配产生的边展示近似标识，并允许用户查看边的依据。
- **Studio 工程的编译配置不统一：** 首版识别常见目录、C/C++ 文件和 include；不同工具链的完整编译参数适配放入后续迭代。
- **VS Code 安装方式多样：** 自动发现只作为便利功能，始终保留手动选择和“复制路径”错误提示。
- **大工程图谱过密：** 默认只显示文件/模块视图，按需展开到符号层级并限制图深度。

## 验收与验证

通过人工验收以下流程：在没有 VS Code 的机器/配置下启动并浏览样例工程；手动选择 VS Code 后从图节点跳到正确文件和行号；导入常见 RT-Thread 工程后查看文件依赖与函数调用；检查不确定调用有标记；确认全部主要界面为简体中文且源码不离开本机。
